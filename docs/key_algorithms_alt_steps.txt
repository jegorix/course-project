Альтернативный набор ключевых алгоритмов

В этом разделе описаны по шагам два алгоритма, более тесно связанных с логикой анализа данных в системе кадрового учета: формирование рейтинга отделов по эффективности затрат и вычисление средней заработной платы по отделу. Оба метода относятся к классу DataManager и позволяют оценивать затраты на персонал по подразделениям.

Входные данные для алгоритмов:
• для функции buildDepartmentsEfficiencyRating: текущие записи сотрудников и отделов, загруженные во внутренние контейнеры DataManager (departments и employees);
• для функции calculateAverageSalaryForDepartment: идентификатор отдела departmentId, выбранный пользователем в интерфейсе; текущие данные о сотрудниках берутся из контейнера employees внутри DataManager.

Алгоритм для функции DataManager::buildDepartmentsEfficiencyRating (рейтинг отделов по эффективности затрат)

Входные данные:
• контейнер departments со списком всех отделов предприятия; для каждого отдела доступен его идентификатор departmentId;
• контейнер employees с записями всех сотрудников; у каждого сотрудника есть departmentId и поле заработной платы salary.

Выходные данные:
• вектор пар (departmentId, efficiency), отсортированный по убыванию коэффициента эффективности затрат.

Шаг 1. Начало.

Шаг 2. Инициализировать пустой вектор результата rating типа std::vector<std::pair<int, double>>, в который будут добавляться пары (идентификатор отдела, коэффициент эффективности).

Шаг 3. Организовать цикл по всем отделам в контейнере departments:
• для каждого отдела получить его идентификатор departmentId;
• перед обработкой сотрудников инициализировать переменные totalSalary = 0.0 (накопление суммы зарплат) и count = 0 (подсчёт количества сотрудников отдела).

Шаг 4. Для текущего отдела организовать вложенный цикл по всем записям сотрудников в контейнере employees:
• пропустить запись, если указатель на сотрудника пустой (record.employee == nullptr);
• сравнить departmentId сотрудника с идентификатором текущего отдела;
• если идентификатор отдела сотрудника совпадает с departmentId, считать его оклад salary, добавить его к totalSalary и увеличить счётчик count = count + 1;
• если идентификатор отдела не совпадает, перейти к обработке следующего сотрудника.

Шаг 5. После завершения вложенного цикла по сотрудникам вычислить коэффициент эффективности затрат для текущего отдела:
• если count == 0 или totalSalary <= 0.0, установить коэффициент efficiency = 0.0 (для отделов без сотрудников или без затрат эффективность не рассчитывается);
• если count > 0 и totalSalary > 0.0, вычислить efficiency как отношение числа сотрудников к суммарным затратам: efficiency = static_cast<double>(count) / totalSalary.

Шаг 6. Добавить в вектор rating пару (departmentId, efficiency) с результатами для текущего отдела.

Шаг 7. Повторять шаги 3–6 для всех отделов в контейнере departments, пока не будут обработаны все подразделения.

Шаг 8. После завершения обработки всех отделов отсортировать вектор rating по убыванию значения коэффициента efficiency:
• использовать стандартный алгоритм std::sort с компаратором, который сравнивает вторые элементы пары (efficiency) двух отделов и возвращает true, если левый элемент больше правого;
• в результате в начале вектора окажутся отделы с наибольшей эффективностью использования фонда оплаты труда.

Шаг 9. Вернуть вектор rating как результат работы функции buildDepartmentsEfficiencyRating.

Шаг 10. Конец функции.

Алгоритм для функции DataManager::calculateAverageSalaryForDepartment (вычисление средней зарплаты по отделу)

Входные данные:
• идентификатор отдела departmentId, выбранный пользователем в интерфейсе (например, из списка отделов);
• текущие записи сотрудников, загруженные в контейнер employees, откуда берутся значения departmentId и salary для каждого сотрудника.

Выходные данные:
• одно вещественное значение averageSalary (тип double), обозначающее среднюю заработную плату сотрудников выбранного отдела; при отсутствии отдела или сотрудников может возвращаться 0.0 или специальное значение (например, -1.0), сигнализирующее об отсутствии данных для расчёта.

Шаг 1. Начало.

Шаг 2. Найти объект отдела по идентификатору departmentId с помощью вспомогательного метода findDepartment:
• если отдел не найден (вернулся nullptr), вернуть 0.0 или специальное значение, обозначающее отсутствие данных, и завершить функцию;
• если отдел найден, сохранить указатель на него для дальнейшей работы.

Шаг 3. Инициализировать две переменные: sumSalary = 0.0 для накопления суммы окладов и count = 0 для подсчёта количества сотрудников отдела.

Шаг 4. Организовать цикл по всем записям сотрудников в контейнере employees (например, от i = 0 до employees.size() - 1):
• для каждого EmployeeRecord получить departmentId сотрудника;
• если departmentId совпадает с идентификатором анализируемого отдела, перейти к следующему шагу;
• если departmentId другой, сразу перейти к следующему сотруднику.

Шаг 5. Внутри цикла для сотрудников нужного отдела:
• считать текущий оклад salary с помощью getSalary();
• прибавить это значение к сумме: sumSalary = sumSalary + salary;
• увеличить счётчик count = count + 1.

Шаг 6. После завершения цикла проверить, больше ли нуля значение count:
• если count == 0, вернуть 0.0 или специальное значение (например, -1.0), означающее, что в отделе нет сотрудников;
• если count > 0, перейти к следующему шагу.

Шаг 7. Вычислить среднюю заработную плату averageSalary как отношение sumSalary / count.

Шаг 8. Вернуть значение averageSalary как результат работы функции.

Шаг 9. Конец функции.

Оба алгоритма относятся к базовой логике DataManager: первый отвечает за корректное управление структурой предприятия при удалении отделов с учётом наличия сотрудников, второй — за простой и наглядный анализ данных о зарплатах конкретного отдела. Вместе они обеспечивают удобное взаимодействие пользователя с системой и наглядное представление информации о сотрудниках, отделах и должностях.
