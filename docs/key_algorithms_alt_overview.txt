та3.1 Разработка схем алгоритмов (два наиболее важных метода)

В процессе разработки программы были реализованы два ключевых алгоритма, обеспечивающих основную «умную» логику приложения кадрового учета. Оба алгоритма связаны с анализом данных о сотрудниках и позволяют оценивать эффективность затрат на персонал по отдельным подразделениям.

Первый алгоритм: рейтинг отделов по эффективности затрат

Этот алгоритм отвечает за сравнительную оценку отделов с точки зрения «эффективности» использования фонда оплаты труда. Под эффективностью в рамках проекта понимается отношение численности сотрудников отдела к суммарным затратам на их заработную плату: чем больше сотрудников удаётся содержать при тех же расходах, тем выше эффективность затрат.

Алгоритм можно разделить на несколько этапов:

1. Подготовка данных по каждому отделу. DataManager проходит циклом по контейнеру departments и для каждого отдела инициализирует счётчики: общую сумму зарплат totalSalary и количество сотрудников count. Это позволяет в дальнейшем рассчитать базовые показатели по каждому подразделению.
2. Сбор информации о сотрудниках. Для каждого отдела выполняется вложенный проход по контейнеру сотрудников employees. Если сотрудник принадлежит текущему отделу (его departmentId совпадает с идентификатором отдела), его оклад добавляется к общей сумме totalSalary, а счётчик count увеличивается на единицу. Таким образом формируются агрегированные данные по затратам и численности.
3. Расчёт показателя эффективности. После обработки всех сотрудников текущего отдела выполняется проверка: если totalSalary равна нулю или в отделе нет ни одного сотрудника, эффективность считается нулевой. В противном случае вычисляется коэффициент эффективности как отношение count к totalSalary. Этот коэффициент добавляется в результирующую структуру вместе с указателем на отдел или его идентификатор.
4. Формирование рейтинга отделов. Когда данные собраны для всех отделов, результирующий список сортируется по убыванию коэффициента эффективности. В начале рейтинга оказываются отделы, в которых затраты на зарплаты относительно численности персонала минимальны (то есть большее количество сотрудников содержится при меньшем фонде оплаты труда).

Полученный рейтинг может использоваться в отчётах и интерфейсе программы для визуального сравнения отделов между собой. Он помогает выявлять подразделения с наилучшим и наихудшим соотношением «численность/затраты» и служит основой для управленческих решений по оптимизации структуры и фонда оплаты труда.

Второй алгоритм: вычисление средней заработной платы по отделу (метод DataManager::calculateAverageSalaryForDepartment)

Этот алгоритм реализует аналитическую задачу — расчёт средней зарплаты сотрудников выбранного отдела. Он также состоит из двух основных этапов:

1. Подготовка и отбор сотрудников отдела. На вход метод получает идентификатор отдела, для которого требуется вычислить среднюю заработную плату. DataManager сначала проверяет существование отдела через findDepartment; при отсутствии соответствующей записи функция возвращает 0.0, так как анализировать нечего. Далее в цикле по контейнеру employees отбираются только те сотрудники, чей departmentId совпадает с заданным. Для каждого такого сотрудника считывается его оклад, который добавляется к общей сумме, и увеличивается счётчик количества сотрудников.
2. Расчёт и возврат среднего значения. После завершения обхода выполняется проверка, найден ли хотя бы один сотрудник в указанном отделе. Если счётчик равен нулю, метод возвращает 0.0 или специальное значение, обозначающее отсутствие данных. В противном случае средняя заработная плата вычисляется как отношение накопленной суммы sumSalary к количеству сотрудников count и возвращается вызывающему коду. Полученное значение может использоваться в отчётах и интерфейсе программы для оценки уровня оплаты труда по отделам.

Оба алгоритма играют важную роль в работе программы: первый обеспечивает безопасное управление структурой предприятия и предотвращает потерю связанных данных, второй — предоставляет удобный инструмент анализа зарплат внутри выбранного отдела. В совокупности они делают систему кадрового учета более надёжной, информативной и удобной для пользователя.
