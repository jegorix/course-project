Алгоритм для функции DataManager::findEmployees

Шаг 1. Начало.

Шаг 2. Получить из интерфейса значения полей фильтра (идентификатор отдела, идентификатор должности, минимальная и максимальная зарплата, фрагмент имени/фамилии) и на их основе сформировать структуру EmployeeSearchFilter:
• для каждого параметра, который пользователь действительно задал, установить соответствующий флаг useDepartmentId, usePositionId, useMinSalary, useMaxSalary, useNameFragment в значение true;
• сохранить введенные числовые и строковые значения в полях структуры (departmentId, positionId, minSalary, maxSalary, nameFragment).

Шаг 3. Инициализировать пустой вектор результатов std::vector<EmployeeRecord> result.

Шаг 4. Пройти по всему контейнеру сотрудников RecordCollection<EmployeeRecord> employees с помощью итераторов begin() и end().

Шаг 5. Для каждой записи EmployeeRecord (далее record) выполнить поочередно проверки в соответствии с активными флагами фильтра:
• если включен фильтр по отделу (useDepartmentId == true), сравнить record.employee->getDepartmentId() с filter.departmentId; при несоответствии перейти к следующей записи;
• если включен фильтр по минимальной зарплате (useMinSalary == true), проверить, что record.employee->getSalary() >= filter.minSalary; иначе пропустить запись;
• если включен фильтр по максимальной зарплате (useMaxSalary == true), проверить, что record.employee->getSalary() <= filter.maxSalary; иначе пропустить запись.

Шаг 6. При активном фильтре по должности (usePositionId == true) определить, является ли текущий сотрудник объектом класса Worker:
• попытаться выполнить динамическое приведение std::dynamic_pointer_cast<Worker>(record.employee);
• если приведение неудачно (сотрудник не Worker), пропустить запись;
• если успешно, сравнить полученный positionId с filter.positionId и при несовпадении перейти к следующему сотруднику.

Шаг 7. При включенном фильтре по фрагменту имени (useNameFragment == true) получить строку полного имени сотрудника через record.employee->getFullName() и выполнить поиск подстроки:
• привести обе строки к одному регистру (при необходимости);
• если nameFragment не входит в полное имя, пропустить текущую запись.

Шаг 8. Если запись прошла все активные проверки, добавить ее в результирующий вектор result с помощью метода push_back.

Шаг 9. После завершения обхода всех сотрудников вернуть вектор result как результат работы функции DataManager::findEmployees.

Шаг 10. Конец функции.

Алгоритм для функции DataManager::undoLastAction

Шаг 1. Начало.

Шаг 2. Проверить, есть ли доступные действия для отмены с помощью метода canUndo() или по размеру вектора undoStack:
• если стек пуст (размер 0), вернуть false и завершить функцию без изменений данных;
• если стек не пуст, перейти к следующему шагу.

Шаг 3. Извлечь верхний элемент из вектора undoStack:
• получить последний объект UndoCommand, содержащий лямбда-функцию undo и строку description;
• удалить этот объект из undoStack (например, с помощью pop_back()).

Шаг 4. Установить флаг undoInProgress = true, чтобы во время выполнения операции отмены не создавались новые команды в стеке отмены (например, при повторном добавлении сотрудника).

Шаг 5. Вызвать сохраненную лямбда-функцию undo():
• восстановить удаленную запись сотрудника или отдела;
• вернуть прежние значения полей (оклад, должность, руководитель и т.п.);
• выполнить любые другие действия, необходимые для полного отката последней операции.

Шаг 6. После завершения отката вернуть флаг undoInProgress в исходное состояние, установив undoInProgress = false.

Шаг 7. Сохранить или обновить текстовое описание последнего отмененного действия в поле, доступном через метод getLastUndoDescription(), чтобы его можно было вывести пользователю.

Шаг 8. Вернуть true, указывая на успешное выполнение операции отмены.

Шаг 9. Конец функции.

Оба приведённых алгоритма обеспечивают ключевую функциональность системы кадрового учета. Первый отвечает за гибкий поиск сотрудников по нескольким критериям и формирование удобного для отображения списка, второй — за безопасную отмену последнего изменения данных с восстановлением предыдущего состояния. Совместное использование этих алгоритмов повышает удобство работы пользователя с программой и надежность хранения информации о сотрудниках, отделах и должностях.
