В процессе разработки программы были реализованы два ключевых алгоритма, обеспечивающих основную «умную» логику приложения кадрового учета. Оба алгоритма тесно связаны с управлением списком сотрудников и поддержанием целостности данных при различных операциях.

Первый алгоритм: поиск сотрудников по заданным критериям (метод DataManager::findEmployees)

Этот алгоритм отвечает за формирование выборки сотрудников в соответствии с параметрами фильтра, задаваемыми пользователем. Алгоритм позволяет отобрать сотрудников по отделу, должности, диапазону заработной платы и фрагменту имени или фамилии. На вход метод получает структуру EmployeeSearchFilter, в которой с помощью булевых флагов отмечается, какие условия поиска реально используются.

На основе переданного фильтра алгоритм последовательно просматривает основной контейнер с записями сотрудников. Для каждой записи выполняется серия проверок: совпадает ли отдел с требуемым, попадает ли оклад в указанный диапазон, соответствует ли должность выбранному идентификатору и содержит ли полное имя сотрудника заданный фрагмент строки. Только если запись удовлетворяет всем активным условиям, она добавляется в результирующий список. В итоге метод возвращает вектор EmployeeRecord, представляющий собой уже отфильтрованный набор сотрудников, готовый к отображению в интерфейсе.

Второй алгоритм: отмена последнего действия (метод DataManager::undoLastAction)

Этот алгоритм реализует механизм «отмены» операций (undo) над данными, что повышает удобство и надежность работы пользователя с системой. Каждый раз при выполнении значимого изменения (например, добавление или удаление сотрудника, обновление отдела или оклада) в стек undoStack помещается команда-обратчик — лямбда-функция, описывающая, как вернуть систему в предыдущее состояние, и текстовое описание действия.

Метод undoLastAction проверяет, есть ли на стеке хотя бы одна команда для отмены, и, если стек не пуст, извлекает верхний элемент. Далее устанавливается специальный флаг undoInProgress, предотвращающий создание новых команд отмены во время выполнения обратной операции. После этого вызывается сохраненная лямбда-функция undo(), которая восстанавливает данные (например, повторно добавляет ранее удаленного сотрудника или возвращает старое значение оклада). По завершении флаг undoInProgress сбрасывается, а пользователю в интерфейсе может быть выведено текстовое описание отмененного действия, получаемое методом getLastUndoDescription().

Оба алгоритма играют важную роль в работе программы: первый обеспечивает гибкий и удобный поиск нужных сотрудников по нескольким параметрам, второй — безопасное выполнение операций за счет возможности отката последнего изменения. В совокупности они делают систему кадрового учета более удобной, надежной и дружественной к пользователю.
